AI · Commerce · Full-stack

Mira

A multi-tenant AI business representative that helps customers find products and gives business owners practical tools to manage their storefronts.

Open the Mira live app ↗ Visit the Mira product site ↗ Browse the Mira source repository ↗

Context

Small businesses need a helpful way to answer product questions and keep catalog and order information current without losing the business context behind each conversation.

Approach

Built with Next.js App Router, TypeScript and Supabase, Mira combines catalog and admin CRUD, stock-aware answers, multilingual support, fuzzy search, manual order tracking and Paystack. Gemini is the primary model, with Groq as a fallback.

Selected build detail

The admin server client uses the logged-in session and an is_platform_admin() RLS policy (admin server client; admin authorization helper). Customer chat instead uses a server-only service-role client and explicit business_id scoping (service-role client; chat route). This separates privileged server access from session-based admin authorization; the route’s tenant filter remains an important application-level boundary.

Trade-off & scope

Privileged database access is kept on the server for chat, while tenant selection is explicit in the request path. The source shows these controls; this portfolio makes no claim of a security audit or measured business impact.

02

AI · Automation · Desktop

Vanta

A Python and Flask multi-model orchestration project with browser automation, retrieval and a live interface.

Explore the Vanta source repository ↗

Context

Vanta brings model-powered workflows and computer/browser interaction into one project, with an interface for observing activity.

Approach

The project combines Python/Flask multi-model orchestration, Playwright, keyword-based retrieval-augmented generation and a Flask/Socket.IO UI.

Selected build detail

The watcher daemon combines file and news watchers, validates configuration and test commands, manages startup and shutdown, and routes alerts to Socket.IO and Telegram.

Trade-off & scope

A daemon coordinating watchers needs explicit lifecycle and configuration handling as well as useful alert destinations. The repository shows those mechanisms; no uptime, accuracy or productivity metrics are claimed here.

03

Machine learning · Research

Sentinel

A cryptocurrency trading-bot project exploring supervised classification and event-based labels.

Context

Market modelling is a noisy prediction problem where a useful experiment begins with a defined target, not a promised outcome.

Approach

The project uses a HistGradientBoostingClassifier and triple-barrier labeling to frame crypto price movement as a classification task.

Selected build detail

Combining a tree-based boosting classifier with triple-barrier labels makes the labeling scheme part of the modelling design: events are framed by price barriers and a time limit rather than a single fixed-horizon label.

Trade-off & scope

No performance metrics, live trading results or independently verified deployment details are available, so none are asserted here. This is presented as a crypto-bot project, not investment advice.
